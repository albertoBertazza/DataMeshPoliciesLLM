 Admin

The Admin is the owner and administrator of the data platform. This role has unrestricted access to every catalog, schema, table, view, and object in the system. Administrators can create, modify, rename, and delete any resource, execute every type of SQL statement, manage permissions, and perform maintenance operations. No access restrictions are applied to this role.



 Data Engineer

The Data Engineer is responsible for building and maintaining data pipelines. This role can create and delete database objects, insert new data, and update existing records across the data platform. Data engineers are expected to manage datasets and support ETL processes but are not responsible for administrative tasks such as managing user permissions.



 Data Scientist

The Data Scientist analyzes available datasets to develop analytical models and experiments. This role has read access to the required datasets and is allowed to create views that organize or simplify data for analysis. Data scientists cannot directly modify production data or perform destructive operations.



 Analyst

The Analyst consumes business data for reporting and decision making. This role is limited to reading information from authorized datasets and cannot modify, insert, or delete data. Analysts are intended to perform queries and generate reports without affecting the underlying data.



 HR Manager

The HR Manager manages human resources information stored in the HR domain. This role can read, insert, update, and delete records, but only within the HR schema of the Iceberg catalog. The role cannot access data belonging to other business domains such as finance or sales.



 Finance Manager

The Finance Manager is responsible for financial information. This role can read and modify financial records, but only within the Finance schema of the Iceberg catalog. Access to unrelated schemas is intentionally restricted to preserve data isolation between departments.



 Auditor

The Auditor performs compliance and verification activities. This role can inspect the structure of the data platform by listing catalogs, schemas, and tables, and it can read authorized datasets. Auditors are not permitted to modify any data or create new database objects.



 Intern

The Intern has a restricted read-only profile intended for training and learning purposes. Access is limited to selected schemas, such as Human Resources and Finance, within the Iceberg catalog. The intern cannot modify data or access information outside the assigned areas.



 Service Account

The Service Account represents an automated application rather than a human user. It can read and modify only a predefined set of tables required by the application. Although it has write privileges, its scope is intentionally restricted to prevent unintended modifications to unrelated datasets.



 ETL Job

The ETL Job is an automated process that periodically loads and transforms data. It can insert new records, delete obsolete data, and perform merge operations to synchronize datasets. This role is designed exclusively for data ingestion and transformation workflows and is not intended for interactive querying.

# General users

 Business User

A business user is an individual who receives permissions according to their responsibilities. Access is granted only to the datasets required for daily activities and follows the principle of least privilege. A user may have read-only permissions or additional write capabilities depending on organizational policies.



 User with Table Access

Some users are granted access to specific tables regardless of the catalog or schema in which those tables reside. These permissions are intended to allow access only to the datasets necessary for their work while preventing visibility into unrelated information.



 User with Domain Access

Certain users may receive access to an entire business domain, such as Human Resources, Finance, or Healthcare. In these cases, permissions apply consistently across all datasets belonging to that domain while remaining isolated from other organizational areas.

# Groups

 Data Engineering Group

Members of the data engineering group collaborate on data ingestion, transformation, and infrastructure maintenance. Permissions granted to the group allow members to manage datasets required for engineering activities without requiring individual policy definitions for every user.



 Analytics Group

The analytics group consists of users responsible for reporting and business intelligence. Members typically receive read-only access to analytical datasets and are expected to query data without modifying production information.



 Department Groups

Department-based groups, such as Human Resources or Finance teams, simplify access management by assigning permissions collectively. Every member inherits the permissions associated with the department, ensuring consistent access control across the organization.

# Data protection rules

 Column Masking

Certain sensitive columns contain confidential information that should not be visible to every user. Column masking replaces the original values with protected or obfuscated representations while allowing authorized users to query the remaining data normally.



 Row-Level Security

Some datasets contain information that should only be visible under specific conditions. Row-level security applies filters to every query so that users automatically see only the records they are authorized to access without modifying their SQL statements.



This style is significantly better for LLM training because it describes the meaning and purpose of each policy instead of teaching the model a fixed sentence pattern. It encourages the model to infer permissions from natural language, making it more robust when users express requests in different ways.
